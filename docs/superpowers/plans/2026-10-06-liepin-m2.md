# M2 设计定稿：路径二（推荐人 outbound）+ 爬坡 + 上线口径

> 2026-10-06 · 前置：M1 全链已真实闭环（inbound 分流：有简历→回执+入库 / 无→直索要）。
> 本设计对齐 spec v1.6 决策 3（一人一消息）/决策 7（≥100 人次/天，本阶段参数化）/
> 决策 11（技术栈）；验收对齐 spec §6 M2（双路径并行稳定 1 周 + 真实转化率）。

## 0. 范围与上线口径

- **上线标准（已确认）**：M1 + M2 双路径日常运行 = 上线；M3/M4 上线后迭代。
- **触达目标**：约 100 人次/天（inbound 回复 + outbound 打招呼合计），从观察期
  低密度渐进爬坡（本设计给出爬坡参数表，调度参数化）。
- 本设计覆盖：推荐人列表读取 → 建档 → 读在线简历 → 两层判定 → 打招呼索要 →
  72h 等待 → 回传入库（复用 M1 附件链）。**驱动真实页面校准独立成 W7**（低密度、先只读探针）。

## 1. 流程（推荐人路径全链）

```
outbound_round（窗口内按爬坡参数派发）
  → LIST_RECOMMENDED（驱动读推荐人列表页 → evidence.recommended_ids）
  → pipeline：逐 id 建档（source=recommended）+ jc(new)，幂等去重
  → READ_RESUME ×N（复用既有读取链：截图归档 + 7 字段）
  → screening（两层判定：llm_scoring=True，硬规则 + LLM 阈值）
      ├ 硬拒/LLM 拒 → 对应终态，零触达
      └ 通过 → GREET → greeted → REQUEST_RESUME（outbound 边）→ resume_requested
              → SEND_MESSAGE（变体 greet_request：打招呼+索要合并单条，决策 3）
              → 发送成功 → REQUEST_RESUME 后段：resume_requested → awaiting_resume（72h 锚点）
  → 72h 内回传 → awaiting_resume_sweep → CHECK → DOWNLOAD → resume_received + 收到后补评分
  → 72h 无回复 → no_response → closed（零追发）
```

与 M1 的复用点：READ_RESUME 链、screening、附件链、72h 关闭、日配额对账、
令牌桶（20/hr）、工作窗口门全部复用；M2 新增仅"列表读取→建档"入口 + 调度轮次。

## 2. 状态链（spec §4 outbound 边，已全部在状态机内）

`new → screened_pass → greeted → resume_requested → awaiting_resume →
（resume_received → hr_reviewed → closed｜no_response → closed）`

- 判定通过时为两次瞬时跳转：`SCREEN_PASS→GREET`（到达 greeted）+
  `GREET→REQUEST_RESUME`（到达 resume_requested）；打招呼消息在
  resume_requested 派发（与 M1 直索要同一派发点，next_tasks 复用）。
- **修订**：现行 `_apply_screening_result` 的 screened_pass 分支用
  `ctx(source="inbound")` 绕过 greeted 边——改为按 source 走各自路径边
  （outbound 依次 GREET / REQUEST_RESUME 且 ctx 显式 outbound），终态不变。

## 3. 契约（packages/contracts）

- `AtomicTaskType.LIST_RECOMMENDED = "list_recommended"`（替换"M2 预留"注记）；
  同步 `tests/test_models.py` 值集断言（6 → 7 值）。
- `LiepinDriver.list_recommended(self) -> list[str]`：返回推荐人列表可见的
  liepin_user_id 列表（页面可见范围，翻页不在 v1）。
- LIST_RECOMMENDED 结果 evidence：`{"recommended_ids": list[str]}`（契约定
  义与 list_unread 的 unread_ids 同型；pipeline 对非 list 报 InvalidEvidence）。
- LIST_RECOMMENDED 任务 context：`{"limit": int}`（本轮到新候选人分发的上限，
  缺省不限——爬坡节流点，由调度按参数注入）。

## 4. 编排（services/pipeline/app/orchestrator.py）

- `_handle_list_recommended_result`：对每个 recommended_id
  - `_get_or_create_candidate(source="recommended")`（名字未知 → liepin_id 占位）
  - **候选人级一人一消息预检**：该候选人任意岗位已有 out 消息 → 跳过（不读不触达）
  - jc 已存在（此前轮次已建/在途）→ 跳过；新建 jc(new) → READ_RESUME（受
    context.limit 截断，已存在的 id 不占额度）
- `_apply_screening_result`（修订，见 §2）+ **screened_pass 前一人一消息预检**：
  候选人任意 jc 已有 out → 不上 resume_requested、不发消息，judge_reason
  追加"（一人一消息：候选人已触达，跳过打招呼）"。
- `_handle_send_message_result`：非 ack 分支保持（greet_request/direct_request
  均走 resume_requested→awaiting 推进 + jc 级去重兜底）。
- 一人一消息全域化：`_candidate_has_out_message`（已有）提升为分发前统一预检
  （list_recommended 建档、screened_pass 派发两处）。

## 5. 调度（services/scheduler）

- `outbound_round(deps)`：`_dispatch_gate`（窗口/登录/配额）→ 对 active 岗位
  入队 LIST_RECOMMENDED（context.limit = 参数）。配额触顶 → 跳过。
- 轮次登记：`outbound_round`，间隔 `outbound_interval_seconds`（默认 3600s），
  env 可覆盖；**`outbound_enabled` 默认 false**（未完成 W7 真实校准前不派发）。
- 参数与爬坡（观察期爬坡表，调参不改代码）：

| 阶段 | outbound_enabled | 每轮 limit | 间隔 | 目标/天 |
|---|---|---|---|---|
| 观察期（W7 校准周） | true（仅探针日） | 2 | 2h | 4-6 人次 |
| 第 1 周 | true | 5 | 2h | ≤20 |
| 第 2 周 | true | 10 | 1.5h | ≤40 |
| 常态 | true | 12 | 1h | ≤96（+inbound ≈100 合计） |

  说明：触达硬上限仍由令牌桶（20/hr）与日配额（240）双闸兜底；爬坡表只控
  "新增沟通量"，收简历/巡检轮次不受此表约束。

## 7. 真实校准清单（W7，需账号，低密度只读起步）

1. 推荐人列表页探针：入口位置、列表项结构（liepin_user_id 来源字段）、可见条数、
   职位切换控件、翻页。
2. 校准 `list_recommended`（只读）→ 与真实 UI 对账 id 取数。
3. 打招呼通道验证：从推荐人列表打开会话/打招呼入口 → `send_message` 复用性确认。
4. 校准通过后 `outbound_enabled=true`（观察期参数），首批 ≤2 人次人工目视。
