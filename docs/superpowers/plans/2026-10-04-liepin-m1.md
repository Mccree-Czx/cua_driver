# 猎聘 HR 辅助招聘系统 — 实施计划（M1 详细 · M2-M4 大纲）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 按 spec v1.6 从零搭建 monorepo，实现 CUA 驱动的猎聘招聘自动化全链路；本计划 M1 细化到任务级（单岗位 inbound 端到端跑通），M2-M4 为大纲。

**Architecture:** Redis arq 队列承载原子任务（scheduler/pipeline 入队 → cua-agent 宿主机 worker 执行 → HTTP 回调 pipeline 落库/推进状态机），pipeline 是 MySQL/MinIO 与状态机的唯一写入口；scheduler 只做时钟与策略（巡检轮次、登录健康检查、配额对账）；screening 独立服务做硬规则+LLM 评分；CUA 层以 `LiepinDriver` 协议隔离真实 SDK 与 Fake 驱动，M1 全程可 mock 验证。

**Tech Stack:** Python 3.12 + uv workspace（FastAPI/SQLAlchemy 2.0/Alembic/minio SDK/APScheduler/arq/pydantic）、Next.js+TS+Tailwind+shadcn/ui（M3，pnpm workspace）、Docker Compose（MySQL 8.4 / MinIO / Redis 7）、Cua Driver 0.30.4（宿主机）、DeepSeek OpenAI 兼容 API（评分文本模型）+ 可换视觉大脑、pytest + Playwright（M3）。

**Spec:** `liepin-hr-assistant-spec-v1.6.md`（工作目录根，计划与 spec 同读）

## Global Constraints（spec 定值，逐字）

- 阈值：LLM 评分 0-100，静态阈值默认 **70**（jobs.llm_threshold），动态阈值（决策 2a）M2 实现，双向调节、保 ≥100 打招呼/天下限。
- 一人一消息：每候选人终身至多 1 条 out 消息（`greet_request` 合并打招呼+索要），**无催促无追发**；72h 无附件 → `no_response → closed`。
- 限频：≤**20 条/小时**（Redis Lua 令牌桶，inbound/outbound 共享）、日上限 **240 条**；触达动作间延时 10-60s、读操作间 5-15s（均匀随机）。
- 合规：在线简历仅存 7 个最小字段（姓名、liepin_user_id、学历、年限、城市、薪资、经历摘要）+ 全页截图；简历仅存候选人主动发送的附件；数据全部本地，不外传。
- MinIO 键（§4）：`resumes/{job_id}/{liepin_user_id}/{姓名}_{岗位}_{YYYYMMDD}[_{HHMMSS}].pdf`（重名加时间戳）；`snapshots/{liepin_user_id}/{YYYYMMDD}_{HHMMSS}.png`（保留历史，最新展示）。
- 预签名 URL ≤**15 分钟**（minio SDK `presigned_get_object`）。
- 状态机（§4，11 状态）逐字遵循；CUA 原子任务失败重试 ≤**3** 次 → 转人工队列。
- 工作窗口默认 **08:00-20:00**（可配置）；每窗口首轮先做登录态检查，失效即暂停全部派发 + 通知人工扫码。
- Token 用量逐任务记录（TaskLog），日预算超阈值降频告警（M4 完整化，M1 只落账）。

## Review Focus（spec 未明说、最可能咬人的输入）

1. **附件非 PDF**（docx/zip 等）→ 不拒绝：按原始扩展名归档（键规则同 `resumes/`，扩展名随文件），M3 预览按扩展名处理。测试：T7 `test_api_task_results.py::test_attachment_non_pdf`。
2. **LLM 输出非法**（score>100、非 JSON）→ schema 校验拒绝 → `degraded`：只存快照+最小字段，不评分不发消息，留待延期重判（spec §5 降级路径）。测试：T5 `test_llm_score.py::test_schema_violation_degrades`。
3. **72h 边界** → 严格 `>` 72h 才关（72h 整点仍等待）。测试：T7 `test_72h.py::test_boundary_exact_72h_still_waits`。
4. **限频边界** → 第 21 条/小时被拒并 defer 重排，第 20 条放行。测试：T10 `test_limiter.py::test_21st_acquire_fails`。
5. **同一会话被重复读取** → 按 `liepin_user_id` 幂等（重复打开不产生第二条消息、不重复建档）。测试：T7 `test_api_task_results.py::test_duplicate_read_idempotent`。
6. **登录态失效发生在轮次中途** → 未执行任务全部暂停，已入队任务照常完成但不派发新任务。测试：T10 `test_rounds.py::test_login_fail_pauses_dispatch`。

## 关键架构决策（7 项，执行时不得重开）

- **D1 派发**：scheduler/pipeline 将 `AtomicTask` JSON 入 arq（Redis）；cua-agent 在宿主机跑 arq Worker，不碰 MySQL/MinIO，执行后回调 pipeline：`POST /internal/tasks/{task_id}/result`、`POST /internal/tasks/{task_id}/artifact`（multipart）。pipeline 是唯一写入口，收到结果后自行推进状态机并入队后续任务。令牌桶 Redis Lua（20/hr）：入队前建议性检查（scheduler）+ 触达前权威检查（worker），耗尽时 `_defer_by` 重排自身。
- **D2 依赖管理**：uv workspace 单根 venv（cua-agent 宿主机运行、开发服务器、全部测试共用）；各服务 Dockerfile 只拷贝自身 + `packages/contracts`。pnpm workspace 仅 `apps/*`。
- **D3 CUA 可测性**：contracts 定义 `LiepinDriver` / `BrainClient` 协议；实现 `FakeLiepinDriver`（JSON 剧本 World：会话、未读标记、简历 fixture、回复时间线含"永不回复"、第 N tick 送达附件、登录态）+ `CuaLiepinDriver`（真实 SDK）。开关 `CUA_DRIVER_MODE=mock|real`。
- **D4 迁移**：Alembic 只在 pipeline（schema 唯一 owner），启动前 `alembic upgrade head`；测试库同样走迁移保持同步。`source/direction/msg_type` 用 MySQL 原生 ENUM；`status` 用 VARCHAR(32) + Python 枚举（状态机会演进）。**spec 补充**：`job_candidate.resume_requested_at`（72h 锚点，`last_touch_at` 不够）。
- **D5 顺序**：见任务列表，每任务独立可审、可拒。
- **D6 M1 验收**：mock E2E 一条命令（T11）；真实账号冒烟为人工清单（T12）。
- **D7 M3 API 面**：`GET /api/jobs`、`POST /api/jobs`、`GET /api/jobs/{id}/funnel`、`GET /api/jobs/{id}/candidates?status=&page=`、`GET /api/candidates/{id}`、`GET /api/job-candidates/{id}/resume-url`、`POST /api/job-candidates/{id}/override`、`POST /api/job-candidates/{id}/rerun`、`GET /api/reports/daily?date=`。

## 任务契约（packages/contracts，后续任务以此为准）

```python
AtomicTask{task_id: UUID, type: AtomicTaskType, job_id: int, job_candidate_id: int|None,
          candidate_liepin_id: str|None, context: dict, attempt: int=0, max_attempts: int=3}
AtomicTaskType = check_login | list_unread | read_resume | send_message | check_attachment
                 | download_attachment（+ list_recommended，M2）
TaskResult{task_id: UUID, outcome: success | failed_retryable | failed_needs_manual,
           evidence: dict, error: str|None}   # evidence: {screenshot_keys, brain_tokens, cost_est, sent_at}
MinimalResume{name, liepin_user_id, education, years_of_experience, city, salary, experience_summary}
ScreenRequest{job_id, resume: MinimalResume, jd_text, hard_rules}
ScreeningResult{hard_pass: bool, hard_reasons: list[str], score: int|None, judge_reason: str,
                status, degraded: bool}
CandidateStatus = {new, screened_pass, rejected_hard, rejected_llm, greeted, resume_requested,
                   awaiting_resume, resume_received, no_response, hr_reviewed, closed}   # 11 态
LiepinDriver: check_login / list_unread_conversations / open_conversation /
              read_online_resume → (PNG bytes, MinimalResume) / send_message /
              check_attachment / download_attachment
BrainClient.verify(screenshot: bytes, criteria: str) -> bool
```
