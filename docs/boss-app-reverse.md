# BOSS直聘 App（招聘端）逆向记录

> 2026-10-16 首探。目标：把 BOSS 的执行端从「macOS 客户端（`boss-app-driver` + CuaDriver）」
> 改成跟猎聘同一套技术——**adb + `uiautomator dump` + 确定性点击流程**。
>
> 锚点表见 [`agent_boss/boss_map.json`](../agent_boss/boss_map.json)；
> 发布职位的填写指南见 [`docs/boss-job-publish-guide.md`](boss-job-publish-guide.md)。

---

## 结论先行

| 问题 | 结论 |
|---|---|
| **能不能 dump 出 XML？** | ✅ **能**。这是整个方案的前提，通过了。 |
| **锚点质量如何？** | ✅ **比猎聘好得多**。见下节。 |
| **登录能自动化吗？** | ❌ **不能**。三道关卡全部必须人工（滑块 / 短信 / 人脸）。 |
| **发职位能自动化吗？** | ⚠️ 暂不能。第二页未探到，且账号刚过风控，不建议近期用脚本操作。 |
| **整体可行性** | ✅ 技术路线成立，但**必须设计成「机器推到关卡前，人过卡，机器接着走」**，不能假设全自动。 |

## ★ 与猎聘最大的差异：锚点策略反过来

| | 猎聘 `com.lietou.mishu` | BOSS `com.hpbr.bosszhipin` |
|---|---|---|
| UI 框架 | **Flutter** | **原生 Android** |
| dump 里的稳定 ID | 几乎没有 | **有完整 `resource-id`** |
| 图标按钮 | 常常无文字 + `clickable=false`，只能靠坐标 | 多半有 rid |
| 锚点策略 | 坐标 + 精确文字 | **优先 rid**，坐标兜底 |

**所以：不要照抄猎聘的 `login_map.json` 写法。** BOSS 的锚点应该以
`com.hpbr.bosszhipin:id/xxx` 为主键，只在少数没有 rid 的节点（如隐私协议页的「同意/拒绝」、
职位管理的五个 tab）才退回文字匹配。

## 设备与连法

- 机型 **华为 EML-AL00 / Android 10**，物理分辨率 1080x2244，**App 可用区 1080x2159**（底部导航占 2094~2159）
- 地址 **`10.99.22.219`**，走无线 adb：`adb connect 10.99.22.219:5555`
- ★ 该手机一度切到安卓 11+ 的「无线调试」TLS 随机端口模式（32907/33955/40553），
  **那种模式未配对就是 `offline`**。要连得先经 USB 跑一次 `adb tcpip 5555`（重启手机后失效）。
- 手机上装了两个 App：`com.lietou.mishu`（猎聘）、`com.hpbr.bosszhipin`（BOSS）

## ★★ 风控：三道关卡，全部必须人工

这是本次最重要的发现，也是方案设计的约束。

| # | 关卡 | 表现 | 能否自动化 |
|---|---|---|---|
| 1 | **网易易盾滑块** | 点「下一步」（提交手机号）后立刻弹出。`WebView` 内，文字只有「易盾验证码」，外面能读到的只有背景图、刷新、切换语音、以及「向右拖动滑块填充拼图」 | ❌ **不能**。`uiautomator` 读不到内部结构。且项目**铁律 3**：「风控页即停，绝不尝试绕过」 |
| 2 | **短信验证码** | 4 格自定义 OTP | ⚠️ 打数字可以，但要人念码 |
| 3 | **★ 人脸识别认证** | 登录成功后弹「检测到您的账号异常，为了保护账号安全，需要验证您的身份信息」，要求「开始人脸识别认证」 | ❌ **绝不该自动化** |

**为什么猎聘能全自动、BOSS 不能**：猎聘那台手机上的账号**早就是被信任的设备**。
BOSS 这个账号在陌生设备/IP 上登录，直接被判异常。

**设计含义**：BOSS 的流程必须是**可暂停、可续跑**的——
机器负责把页面推到关卡前，然后停下来等人；人过完卡，机器从当前页面继续。
不能写成一条直线跑到底的脚本。

### 危险邻居：人脸墙页的「更多操作」

那个菜单里除了「退出登录」，还有 **「解绑实名」**——点错会解除账号的实名绑定。
**只按坐标精确点，任何不确定都停手。**

## 登录链路（实测走通一次）

```
启动 App
  └─ 隐私协议弹窗        点「同意」(745,1746)  ★无 rid，靠文字精确匹配
      └─ 身份选择        点 cl_boss_card「我要招人」(540,1561)
          └─ 登录页      勾 checkbox → 填 et_phone → 点 btn_confirm「下一步」
              └─ ★滑块   出现即停手，等人手动过
                  └─ 短信码  填 et_code（★输满 4 位自动提交，没有「再点下一步」）
                      └─ ★人脸墙  出现即停手，等人本人过
                          └─ 登录后勋章引导  点 tv_page_no「暂不点亮」跳过
                              └─ 主界面 MainActivity
```

**两个反直觉的点：**

1. **`tv_login_title` 旁边没有密码登录。** BOSS 招聘端只有「手机号 + 短信码」。
   猎聘那套「密码加密存档、换号失败时登回旧号」在 BOSS 上**用不了**——换号必然要人收验证码。
2. **验证码输满 4 位自动提交。** 输完立刻 dump 会看不到那 4 个格子——页面已经跳走了。
   如果照猎聘的写法「填完再点下一步」，会点空。

## 主界面与导航

底部四个 tab（`cl_tab_1..4`，**必须点容器，`tv_tab_N` 的 bounds 是 `[0,0][0,0]`**）：

| tab | rid | bounds |
|---|---|---|
| 牛人 | `cl_tab_1` | [0,2094][270,2159] |
| 搜索 | `cl_tab_2` | [270,2094][540,2159] |
| 消息 | `cl_tab_3` | [540,2094][810,2159] |
| 我的 | `cl_tab_4` | [810,2094][1080,2159] |

**判定「在不在主界面」**：能同时找到 `cl_tab_1` 与 `cl_tab_4`（至少认两个，
照搬猎聘 `ensure_main_tabs` 的教训——只认一个会被页面里碰巧出现的同名元素骗过）。

**「我的」页**顶部三个图标：`iv_switch_identity`（切换身份）、`iv_scanner_entrance`（扫一扫）、
`iv_general_settings`（设置）。职位管理入口是 `rl_position`（[24,847][1056,1027]）。

⚠️ 「我的」页中部 `rvPropList` 里那三个是**付费推广**（优先曝光·曝光刷新卡 / 置顶职位·置顶卡 /
群发消息·牛人炸弹Pro）——**绝不要点**。跟猎聘的「火爆刷」同类。

## 职位管理与发布

**职位管理页**（`PositionListManagementActivity`）：
五个 tab（全部 / 开放中 / 待开放 / 审核未通过 / 已关闭）是**无 rid 的 TextView**，靠文字匹配。
列表项是 `tv_job_name` / `tv_job_state` / `fl_job_info`。

`fl_job_info` 的格式给出了 BOSS 的目标字段形态：

```
上海·四川北路  |  本科  |  3-5年  |  18-25K·13薪  |  全职
```

对比猎聘的 `上海-虹口区 | 本科 | 3年以上 | 30-50k·13薪`——结构一样，但两处要换算：
**① BOSS 要商圈级城市（不是区）；② BOSS 的经验用区间（`3-5年`），猎聘用「N年以上」。**

**发布表单**（`MOCreatePositionActivity`）：两步向导，本次**只探到第一页**。

```
① 填写基本信息 ──── ② 选择职位要求（★未探到）
   招聘类型：社招全职 / 应届校园招聘 / 实习生招聘 / 兼职招聘
   职位名称：文本框
   职位描述：文本框（必填，有红点）
   底部：btn_save —— ★ rid 叫 save，文字其实是「下一步」
```

★ **页面原文提示**：`招聘类型、职位名称、职位类型和工作城市发布后不可修改`。
职位名和城市发出去就定死了，想改只能下架重发。

★ **退出表单的坑**：点 `iv_back` 会弹一个**引导框**（「AI帮我写 / 复制历史职位」），
**它不是丢弃确认**——真正的关闭入口是弹框下方的 `iv_close`（约 540,1599）。
关掉后再按一次 BACK 才是干净退出（实测不留草稿）。

## 下一步建议

1. **先别急着自动化**。这个账号刚被风控判过异常，近期用脚本操作风险高。
2. 人工用几天，把账号养回正常状态，同时观察风控是否复现。
3. 期间可以做**只读**的部分：把牛人/消息两个 tab 的锚点摸出来。
4. 真要自动化时，**从只读动作开始**（读职位列表、读候选人），
   写操作（打招呼、发职位）最后再上，且必须带「停手闸门」。
